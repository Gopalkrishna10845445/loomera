# 4. TASK TWO — SECURE SERVER-SIDE SESSIONS

Implement secure server-side session management.

### Cookie requirements

Use appropriately configured cookies:

* HttpOnly: true
* Secure: true in production
* SameSite: Lax or stricter where compatible
* Path: /
* Appropriate expiration

Do not expose session identifiers to frontend JavaScript.

### Session management

Implement:

* Session creation.
* Session validation.
* Session expiration.
* Session revocation.
* Logout invalidation.
* Session rotation after authentication where appropriate.

Use cryptographically secure random session identifiers.

Store only appropriately protected session identifiers or tokens in the database.

Never trust an identity supplied through request parameters or browser state.

The authenticated customer identity must be obtained from the verified server-side session.

### Security considerations

Protect against:

* Session fixation.
* Session hijacking.
* Cross-site scripting exposure of session credentials.
* CSRF attacks.
* Brute-force login attempts.
* Unauthorized session reuse.

Use appropriate CSRF protection for state-changing endpoints, considering the application's cookie and request architecture.

# 8. TASK SIX — ANONYMOUS CART MERGE AFTER LOGIN

Implement a safe cart synchronization mechanism.

### Expected customer experience

Example:

A visitor adds:

* Linen Shirt — Size M — Quantity 2
* Cotton Trousers — Size L — Quantity 1

The visitor then logs in.

The anonymous cart should be merged into the authenticated customer's PostgreSQL cart.

### Merge rules

1. Read anonymous cart data.
2. Validate product IDs.
3. Validate variant IDs.
4. Validate product availability.
5. Validate quantities.
6. Reconcile duplicate product variants.
7. Merge quantities according to the established cart policy.
8. Revalidate maximum permitted quantities and stock.
9. Recalculate prices using database values.
10. Commit the operation transactionally.

### Idempotency

The merge must not duplicate items when:

* The login request is retried.
* The browser refreshes.
* Network requests are repeated.
* The merge endpoint is called more than once.

Use an appropriate transaction and idempotency strategy.

### Failure handling

If merging fails:

* Do not silently discard the anonymous cart.
* Do not corrupt the authenticated cart.
* Return a meaningful error.
* Preserve recoverable anonymous cart data.
* Allow a safe retry.

Test partial failures and concurrent requests.
